# Edge Tab Auto Organizer Requirements

## 1. Purpose

Microsoft Edgeで開きっぱなしになったタブを、ユーザーが安全に把握・整理・一括クローズできるようにする。

特に以下の2つを解決する。

- しばらくアクセスしていないタブを自動的に見つけ、グループ化して一括クローズしやすくする
- あるタブから発生した別タブ群を、同じトピック・動機に属するものとして自動的にグループ化する

## 2. Target Users

- 調査、比較、開発、購買検討などで多数のタブを開きがちなEdgeユーザー
- タブを閉じる判断は自分でしたいが、閉じる候補の抽出や分類は自動化したいユーザー
- トピック単位でタブ群を扱いたいユーザー

## 3. Problems

### 3.1 Inactive Tabs

ユーザーはタブを後で読むつもりで残すが、時間が経つと以下の問題が起きる。

- どのタブが古いか分からない
- 不要なタブを1つずつ確認して閉じるのが面倒
- 誤って必要なタブを閉じる不安がある
- タブが増えすぎて現在の作業対象が見えにくくなる

### 3.2 Spawned Tabs

検索結果、記事、ドキュメント、ECサイト、Issue、Pull Requestなどから複数の関連タブが発生することがある。

これらは同じトピック・動機に属することが多いが、ブラウザ上では散らばってしまう。

### 3.3 Stale Or Duplicate Groups

ブラウザ利用を続ける中で、過去のグループや同名グループが増えて、垂直タブ上で整理しづらくなることがある。

タブグループは、その中にタブが残っている限りブラウザ上に残る。折りたたまれている場合、ユーザーには「使われていないグループ」に見えやすい。

## 4. Functional Requirements

### FR-1 Track Tab Activity

拡張機能は各タブについて、整理判断に必要なメタデータを記録する。

- タブID
- ウィンドウID
- URL
- タイトル
- 最終アクティブ時刻
- 作成時刻
- 親タブIDまたは起点タブID
- グループ化状態

### FR-2 Detect Inactive Tabs

拡張機能は、一定時間アクセスされていないタブを「非アクティブ候補」として判定する。

MVPの初期値:

- 非アクティブ判定しきい値: 24時間
- 除外対象: ピン留めタブ、音声再生中タブ、アクティブタブ

ユーザーは後続バージョンでしきい値を変更できるようにする。

### FR-3 Group Inactive Tabs

非アクティブ候補は、自動的に専用タブグループへ移動できる。

MVPのグループ名:

- `Inactive`

期待動作:

- 既存の`Inactive`グループがある場合は再利用する
- 対象タブを閉じる前に、ユーザーが内容を確認できる状態にする
- 自動クローズはMVPでは行わない

### FR-4 Bulk Close Support

ユーザーは非アクティブグループ内のタブを一括で閉じられる。

安全要件:

- 一括クローズ前に確認を表示する
- ピン留めタブは一括クローズ対象に含めない
- クローズ後に復元できるよう、閉じたタブのURL・タイトル・時刻を履歴として保存する

### FR-5 Detect Spawned Tabs

拡張機能は、あるタブから開かれた新規タブを検出し、起点タブとの関係を記録する。

対象例:

- リンクを新しいタブで開いた
- 検索結果から複数ページを開いた
- ドキュメント内リンクから参照先を開いた

制約:

- ブラウザAPIで親子関係を取得できないケースでは、直前にアクティブだったタブや opener 情報から推定する
- 推定である場合は、内部メタデータに信頼度を持たせる

### FR-6 Auto Group Spawned Tabs

起点タブから発生したタブ群は、同じトピックとして自動的にグループ化する。

期待動作:

- 起点タブと派生タブを同じタブグループへ入れる
- 既に起点タブがグループに属している場合は、そのグループを再利用する
- 起点タブが未グループの場合は、新しいグループを作成する
- グループ名は起点タブのタイトルまたはドメインから生成する

### FR-7 Manual Review

ユーザーは拡張機能のポップアップまたは管理画面で、整理候補を確認できる。

最低限表示する情報:

- グループ名
- タブ数
- 最終アクセスからの経過時間
- タイトル
- ドメイン
- 一括クローズ操作

### FR-8 Exclusion Rules

ユーザーまたはシステムは、重要なタブを自動整理対象から除外できる。

MVPの除外条件:

- ピン留めタブ
- 音声再生中タブ
- Edge内部ページ
- 拡張機能ページ
- ユーザーが明示的に除外したドメイン
- ユーザーがポップアップで明示的に除外したURLまたはURLプレフィックス

対象外URLは、起点タブ由来の自動グループ化、ドメイン/URLルール、自動非アクティブ整理の対象にしない。
また、対象外URLと一致するタブは、重複URLの自動フォーカスおよび重複タブの自動クローズの対象にしない。

制約:

- `http` または `https` のURLを登録できる
- URL末尾が`/`の場合は、そのホスト配下を対象外にできる
- URLフラグメントは比較時に除外する
- 設定は`chrome.storage.local`に保存し、外部へ送信しない

### FR-9 Domain Group Rules

ユーザーは、手動で作成したタブグループを特定ドメインまたは特定URLの既定グループとして保存できる。

期待動作:

- タブ右クリックメニューから、対象タブのドメインを現在所属しているタブグループ名に紐づける
- タブ右クリックメニューから、対象タブのURLを現在所属しているタブグループ名に紐づける
- 現在アクティブなタブのドメインを、現在所属しているタブグループ名に紐づける
- 以後、同じドメインのタブが開かれた場合は、そのグループへ自動的に移動する
- 以後、同じURLのタブが開かれた場合は、そのグループへ自動的に移動する
- URLルールはドメインルールより優先する
- 同じウィンドウ内に対象グループ名が存在する場合は再利用する
- 対象グループ名が存在しない場合は新しく作成する
- ドメインルールは、起点タブ由来の自動グループ化より優先する
- 既に何らかのタブグループに所属しているタブは、自動的に別グループへ移動しない
- 自動移動先のドメインルールグループは、タブが隠れないように展開する

制約:

- MVPではドメイン単位で判定し、URLパス単位のルールは扱わない
- URLルールはフラグメントを除いたURLの厳密一致で判定する
- MVPでは手動グループ化そのものはEdge標準UIで行い、拡張機能はルール保存と自動適用を担当する
- ドメインルール保存の主導線はタブ右クリックメニューとする
- 日本語ロケールでのタブ右クリックメニュー名は`このドメインを常にこのグループで開く`とする
- 日本語ロケールでのURL用タブ右クリックメニュー名は`このURLを常にこのグループで開く`とする
- 手動作成グループや他ツールが作成したグループの意図を優先し、既存グループ所属タブは移動対象から除外する
- タブバーや垂直タブのスクロール位置そのものはブラウザUIの管理下にあり、MVPでは直接制御しない

### FR-10 Bookmark Navigation Deduplication

ユーザーがお気に入り、履歴、または新規タブでURLを開いたとき、同じURLのタブが既に存在する場合は、その既存タブをアクティブにする。

期待動作:

- `webNavigation` の `auto_bookmark` 遷移を検出する
- 開こうとしたURLと同じURLの既存タブを探す
- 既存タブが見つかった場合は、そのタブとウィンドウをアクティブにする
- お気に入りクリックで置き換わった元タブは、可能な範囲でブラウザバックする
- 新規タブの重複判定は読み込み完了後に行い、検索エンジンなどの中間リダイレクトURLでは閉じない
- 新規タブで開かれたURLが既存タブと重複する場合は、既存タブをアクティブにして重複新規タブを閉じる

制約:

- ブックマーク自体のURLは書き換えない
- ブラウザUIのお気に入りクリックを事前にキャンセルするのではなく、遷移後に補正する
- 置き換わった元タブを明示的なURL再指定で戻す処理は行わず、ブラウザ履歴の戻る操作に任せる
- URL更新時のドメインルール適用は、お気に入り/履歴の重複タブ判定より後に行う
- 新規タブの重複URL判定は、ドメインルール適用や起点タブ由来グループ化より前に行う
- URL比較ではフラグメントを除外する

### FR-11 Single Expanded Tab Group

ユーザーが作業中の文脈に集中できるよう、同一ウィンドウ内で展開されているタブグループを原則1つに保つ。

期待動作:

- アクティブタブがタブグループに所属している場合、そのグループを展開する
- 同じウィンドウ内の他のタブグループは折りたたむ
- アクティブタブがタブグループに所属していない場合、同じウィンドウ内のタブグループを折りたたむ
- ドメイン/URLルールや起点タブ由来の自動グループ化でグループが展開された場合も、他グループを折りたたむ

制約:

- タブグループの折りたたみ/展開はブラウザ標準UIの状態を更新する
- ユーザーが手動で複数グループを開いた場合でも、次にアクティブタブが変わると1グループ展開へ揃える

### FR-12 Duplicate Group Cleanup

ユーザーは、同一ウィンドウ内で同じ名前を持つタブグループを統合できる。

期待動作:

- ポップアップから重複グループ統合を実行できる
- 同一ウィンドウ内で同じグループ名を持つグループを1つにまとめる
- 統合時は、後続グループ内のタブを先頭グループへ移動する
- 名前が異なるグループは自動統合しない

制約:

- タブが存在するグループは、ブラウザ仕様上「空」とはみなされない
- タイトルが異なる過去グループの削除やクローズは、誤整理を避けるためMVPでは自動化しない

## 5. Non-Functional Requirements

### NFR-1 Safety

- ユーザー確認なしにタブを閉じない
- 自動整理はグループ化までを基本とする
- 一括クローズ履歴を保存する

### NFR-2 Privacy

- タブ情報はローカルに保存する
- 外部サーバーへURL、タイトル、閲覧履歴を送信しない
- 初期実装ではクラウド同期を行わない

### NFR-3 Performance

- タブ更新イベントごとに重い処理を行わない
- 定期スキャンは低頻度にする
- 多数タブ環境でも操作の遅延を避ける

MVP目安:

- 300タブ程度で実用的に動作する
- 定期スキャン間隔は15分以上

### NFR-4 Reliability

- 拡張機能の再起動後もメタデータを復元できる
- タブIDが変わるケースを考慮し、URL・作成時刻・ウィンドウIDなどで補助的に照合する
- API失敗時はユーザー操作を壊さずログに残す

### NFR-5 Usability

- 自動整理結果をユーザーが理解できる
- 一括クローズ対象が明確に分かる
- 誤操作を防ぐ確認導線を持つ

## 6. Constraints and Assumptions

- 対象ブラウザはMicrosoft Edge
- 拡張機能はManifest V3を前提とする
- タブグループAPIが利用可能であることを前提とする
- 初期実装ではローカルストレージのみを使う
- AIによる意味解析や外部API分類はMVPに含めない

## 7. MVP Scope

MVPで実装する。

- タブの最終アクティブ時刻を記録する
- 24時間以上アクセスしていないタブを検出する
- 非アクティブタブを`Inactive`グループへまとめる
- 起点タブから発生した可能性が高い新規タブを同一グループへまとめる
- 手動グループ化したドメインを既定グループとして保存し、以後自動適用する
- お気に入り、履歴、または新規タブで開いたURLが既存タブにある場合、その既存タブをアクティブにする
- アクティブタブが属するグループだけが展開され、他グループは折りたたまれる
- 同名の重複タブグループをポップアップから統合できる
- ポップアップから候補一覧を確認し、一括クローズできる
- 一括クローズ履歴をローカルに保存する

MVPでは実装しない。

- 完全自動クローズ
- クラウド同期
- AI分類
- 複数端末連携
- 高度な自然言語トピック名生成

## 8. Acceptance Criteria

- タブを切り替えると、対象タブの最終アクティブ時刻が更新される
- 24時間以上アクセスされていない通常タブが`Inactive`グループへ移動される
- ピン留めタブ、音声再生中タブ、現在アクティブなタブは`Inactive`グループへ移動されない
- あるタブから新しいタブを開いた場合、起点タブと派生タブが同じグループに入る
- 起点タブが既存グループに属している場合、派生タブはそのグループに入る
- 現在のタブがグループに属している場合、そのドメインをグループ名へ紐づけて保存できる
- タブ右クリックメニューから、そのタブのドメインをグループ名へ紐づけて保存できる
- タブ右クリックメニューから、そのタブのURLをグループ名へ紐づけて保存できる
- 保存済みドメインのタブを開くと、同名グループへ自動的に移動される
- 保存済みドメインのタブでも、既に別グループに入っている場合は移動されない
- お気に入り、履歴、または新規タブで既に開いているURLを開いた場合、既存タブがアクティブになる
- タブを切り替えると、同一ウィンドウ内で展開されているタブグループが最大1つになる
- 同一ウィンドウ内に同名グループが複数ある場合、統合操作で1つにまとめられる
- 一括クローズ前に確認が表示される
- 一括クローズ後、閉じたタブのURL・タイトル・クローズ時刻が保存される
- 外部ネットワークへタブ情報を送信しない

## 9. Open Questions

- 非アクティブ判定の初期値は24時間でよいか
- 起点タブ自体も派生タブグループへ含めるか、派生タブのみをまとめるか
- グループ名はタイトル由来、ドメイン由来、または手動名のどれを優先するか
- 一括クローズ履歴は何件または何日保持するか
- 非アクティブグループ化は完全自動か、ユーザー操作で実行するか
- ドメインルールを削除・編集する管理画面をMVPに含めるか
